  ```php
  if ( isset( $_SERVER['HTTP_X_FORWARDED_PROTO'] ) && 'https' === $_SERVER['HTTP_X_FORWARDED_PROTO'] ) {
      $_SERVER['HTTPS'] = 'on';
  }
  ```
- [ ] **`AGH_PRIVATE_DIR` webgyökéren kívül** (ajánlott), a PHP által írható könyvtárral:
  ```php
  define( 'AGH_PRIVATE_DIR', '/var/www/agh-private' ); // NEM a public_html / webgyökér alatt
  ```
  Ilyenkor az eltávolítás (`uninstall.php`) csak a plugin saját, UUID-nevű mappáit és a próbafájlt törli.
- [ ] **Ha a könyvtár az `uploads` alatt marad – Nginx tiltó szabály** (a `.htaccess`-t az Nginx nem olvassa):
  ```nginx
  # a server {} blokkba, a PHP-location elé
  location ~* ^/wp-content/uploads/agh-private-[a-z0-9]+/ {
      deny all;
  }
  ```
  Eltérő `uploads`-útvonalnál igazítsd. Apache-nál ellenőrizd, hogy az `AllowOverride` engedi a `.htaccess`-t; IIS-en a plugin `web.config`-ot ír.
- [ ] **Ellenőrzés:** `curl -I https://<domain>/wp-content/uploads/agh-private-<utótag>/agh-probe.txt` → 403 vagy 404; az admin felületen nem szerepel „A védett tárhely könyvtár HTTP-n keresztül elérhető!” hiba.
- [ ] **Valódi cron:** `DISABLE_WP_CRON` + rendszer-cron, hogy a sor (`agh_cron_queue`, percenként) és a megőrzési takarítás (`agh_cron_daily`) biztosan fusson. Kézi parancsok: `wp agh queue run` (vagy `wp agh queue --seconds=N`), `wp agh retention`, `wp agh status` (`includes/Cli/Command.php`).
- [ ] **PHP-futásidő és feladatzár:** a feladatzár alapértékekkel 513 s (`JobQueue::lock_seconds()`). Ha egy worker idő előtt leáll (pl. `max_execution_time`), a feladat és a párhuzamossági hely legfeljebb ennyi ideig foglalt marad (C.12). A cron-/CLI-worker `max_execution_time`-ja legyen elég a leghosszabb szolgáltatói hívásra.
- [ ] PHP ≥ 8.0 és WordPress ≥ 6.2 (`autogrowehome.php`), `mbstring` (nélküle a plugin nem tölt be), `sodium`, `gd`, `zip`, `json` kiterjesztés – a Rendszerállapot oldal mutatja. Éles MySQL/MariaDB-n futtasd le a tesztsorokat egy staging-példányon (csak SQLite-on mértük).
- [ ] **Teljesoldalas gyorsítótár** ne tároljon bejelentkezett felhasználónak szóló oldalt (a loader-konfiguráció bejelentkezve `wpNonce`-t tartalmaz, `Frontend::footer()`), és a REST-válaszokat (`/wp-json/agh/v1/…`) ne gyorsítótárazza.

### Tesztelési korlátok (biztonsági szempontból)

- A szolgáltatói (Magnific, Anthropic) és licencszerver-hívások szimuláltak (`pre_http_request`), az e-mailek elfogottak (`pre_wp_mail`); éles kulccsal semmi nem futott.
- Csak SQLite-on futott (WordPress 7.2-alpha + SQLite Database Integration 3.1.0); az atomikus `INSERT IGNORE` + feltételes `UPDATE` (napi keret, job-claim, slot- és poll-bérlet, kerettérítés) viselkedése MySQL/MariaDB-n nem mért. A valós HTTP-párhuzamossági mérés a javítások előtt készült, utána nem ismételtük meg.
- Süti-flagek, letöltési válaszfejlécek, a webhook-token ellenőrzése, admin-nonce-ok és az admin felület kimeneti escape-je: csak kódolvasással ellenőrizve.
- Nginx/Apache/IIS tiltó szabályok, valódi HTTPS és proxykörnyezet: nem tesztelt.
